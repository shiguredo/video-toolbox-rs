# `test_supported_codecs` が「全 Mac で H.264/HEVC 対応」を前提にしている

Created: 2026-04-01  
Model: Composer 2 Fast

## なぜこの対応が必要か

`src/lib.rs` の `test_supported_codecs` は **H.264 と HEVC のデコード・エンコードが必ず `supported` である**ことを `assert!` している。将来の macOS・仮想化環境・特殊構成では **失敗しうる**。CI の runner 種類を固定しない場合、**フレーク**の原因になる。

## 現状

- **場所**: `src/lib.rs` の `tests::test_supported_codecs`

## 望ましい対応の方向（案）

- **サポートされていること自体をテストの不変条件とする**なら、README または CI ドキュメントに **想定環境（例: Apple Silicon + 特定 OS 以上）**を明記する。
- または、**環境によってスキップ**する・**緩い検証**（例: エントリが存在する・件数が 4）に変更する。

## 解決の完了条件

- テストの前提と CI の期待が **文書またはテストコードのいずれかで一貫**していること。

## レビュー（第 1 回）— ソース照合

- 現在の `test_supported_codecs` は `codecs.len() == 4`、H.264/HEVC の `decoding.supported` / `encoding.supported` を `assert!`、VP9/AV1 の `encoding` を否定。失敗点は **主に H.264/HEVC の「必ず true」**部分。

## レビュー（第 2 回）— CI との整合

- `.github/workflows` の runner が **macOS のどのラベルか**を確認し、README の動作要件（例: arm64）と **同じ前提**をテストに書けるか検討。

## レビュー（第 3 回）— 「緩い検証」への変更リスク

- 件数だけ・存在だけに弱めると、**`supported_codecs` が空や欠落を返す回帰**を逃す。緩和と回帰検知の **バランス**が必要。

## レビュー（第 4 回）— スキップの表現

- `#[ignore]` はプロジェクト規約で禁止。環境検出して **早期 `return Ok(())`** は既存の VP9/AV1 テストと同型。H.264/HEVC をそこまで落とすと **テストの意味が薄い**ので、**文書で前提を固定**する案と比較すること。

## レビュー（第 5 回）— 仮想化・将来 OS

- 将来の macOS で VT のポリシーが変わると **「全 Mac」前提が崩れる**。テストを緩めるより **前提を README に書く**方が長持ちする場合がある。

## レビュー（第 6 回）— 重複テスト

- `init_vp9_decoder` は削除済みで `vp9_decoder` が残る。`supported_codecs` の検証は **このテストと重ならない**（役割が違う）。重複整理は不要。

## レビュー（第 7 回）— 失敗時のデバッグ性

- フレークしたとき **どの assert が落ちたか**が分かるよう、現状のまま assert を分割してもよい（必須ではない）。

## レビュー（第 8 回）— 完了条件の再解釈

- 「文書またはテストの一貫」は、**README に「CI は macOS 14+ Apple Silicon」**の一行でも達成しうる。テスト変更は必須ではない。

## レビュー（第 9 回）— ローカル開発者

- 古い Mac の開発者が `cargo test` で落ちるのを許容するか。**許容なら README に明記**が親切。
