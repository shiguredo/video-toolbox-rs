# `Encoder::encode_pixel_buffer` の `pixel_buffer_ptr` 前提を公開 API で明確化する

Created: 2026-04-01  
Model: Composer 2 Fast

## なぜこの対応が必要か

`encode_pixel_buffer` は外部ポインタに `CFRetain` し、`VTCompressionSessionEncodeFrame` に渡す。**有効な `CVPixelBuffer` でない**と C / CoreVideo 側の **未定義動作**になりうる。一方、**解像度やアスペクトが `EncoderConfig` と食い違う**場合は、必ずしも即クラッシュせず **不正なエンコード結果・同期ずれ**になる可能性がある。これを **メモリ安全の Safety** と **正しさの前提**に混同しないこと。

## 現状

- **場所**: `src/lib.rs` の `Encoder::encode_pixel_buffer`
- **検証**: `CVPixelBufferGetPixelFormatType` を `EncoderConfig.pixel_format` と照合。解像度は **未照合**。

## 問題（リスク）

- フォーマット以外の誤用が # Safety に書かれていないと、利用者が **「クラッシュしなければ正しい」** と誤解しうる。
- **前任レビューで甘かった点**: 「検証不能」で済ませ、**解像度不一致が UB ではなく品質・仕様違反**であることの区別が弱かった。

## 望ましい対応の方向（案）

- # Safety に **有効な `CVPixelBuffer`** に加え、**幅・高さ・プレーン構成がセッションと整合する**ことを **利用者責務**として明記する。
- オプションで `CVPixelBufferGetWidth` / `GetHeight` と `EncoderConfig` を照合し、不一致は **`Result::Err`** またはドキュメントで **未定義の出力**と書く。

## 解決の完了条件（厳格）

- 「ピクセルフォーマットが合えばよい」という **誤解を招く一文が残っていない**こと。
- 解像度を **実行時検証しない**方針なら、その **リスク**を Safety かドキュメントのどちらかで **明示**すること。

## 厳格レビュー（第 2 パス）

1. **ソース照合**: 解像度チェックなし。記述は正しい。
2. **不足していた観点**: UB と **論理誤エンコード**の区別。
3. **誤解しやすい点**: `CFRetain` 後はオブジェクト寿命は延びるが、**中身の解像度**は別。
4. **0022 との境界**: 本 issue は **入力バッファ**、0022 は **コールバックの `Sender`**。
5. **前回からの差分**: 完了条件で **誤解を残さない**ことを明文化。

## 解決方法

Completed: 2026-04-01

- `encode_pixel_buffer` の `# Safety` に、解像度・プレーン整合が呼び出し側責務であり本関数はピクセルフォーマットのみ検証する旨を追記した。
