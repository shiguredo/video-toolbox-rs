# on_encoded/on_decoded のエラー時にユーザーデータを付与すべきか検討する

Created: 2025-05-13
Model: deepseek-v4-pro

## 背景・根拠

現在 `EncodeHandler::on_encoded` と `DecodeHandler::on_decoded` のコールバックは以下のシグネチャを持つ:

```rust
fn on_encoded(&mut self, result: Result<EncodedFrame<Self::UserData>, Self::Error>);
fn on_decoded(&mut self, result: Result<DecodedFrame<Self::UserData>, Self::Error>);
```

エラー時（`Err` 側）にはユーザーデータが含まれないため、どのフレームに対してエラーが発生したのかをユーザーが特定できない。エラー時にもユーザーデータを付与できれば、ユーザーはエラーの原因となったフレームを特定しやすくなる。

## 検討事項

### 1. 復帰不可能なエラーならユーザーデータを付与する意味があるか

エラーが復帰不可能（エンコーダ/デコーダを再生成する必要がある）場合、ユーザーは結局すべての状態を作り直すことになる。その場合、どのフレームでエラーが発生したかの情報に実用的な価値があるか疑問が残る。

### 2. 復帰可能かどうかをライブラリ側のみで判断できるか

Video Toolbox が返すエラーが復帰可能かどうかはライブラリ側だけでは判断できない場合がある。例えばリソース不足は一時的かもしれないし、フォーマット不正は恒久的かもしれない。ユーザーのユースケースによっても判断が変わる。

### 3. エラー時にユーザーデータを正しく紐付けられるか

Video Toolbox のコールバックでエラーが返された場合、そのエラーが本当にどの入力フレームに対応するものなのかが曖昧になるケースがありうる。例えば:

- 非同期でエンコード/デコードが行われるため、エラー発生時点で対応するフレームの `source_frame_info` が取得できない可能性がある
- Video Toolbox 内部でバッファリングされたフレームに対するエラーの場合、コールバックに渡される情報だけでは紐付けが困難な場合がある

## 対応方針

まず以下を調査した上で対応可否を判断する:

1. Video Toolbox のエラーコールバックで `sourceFrameRefcon`（エンコーダ）や `sourceFrameRefCon`（デコーダ）が取得可能かどうか
2. 取得可能な場合、それが確実に正しいフレームに紐付いているかどうか
3. 上記を踏まえた API 設計の選択肢（例: `Result<EncodedFrame<T>, (Self::Error, Option<T>)>` のような形）

調査結果に基づいて、対応する・しない・一部のみ対応する、のいずれかを決定する。
